# 故障排查

按顺序检查：设备联网 → 电脑程序 → 虚拟声卡 → 输入法快捷键 → 实际音频 → 识别文字。

| 现象 | 判断与处理 |
| --- | --- |
| 等待电脑 | 启动本包的转发器；设备/电脑同局域网；检查访客隔离、专用网络防火墙、VPN 的局域网路由 |
| 电脑已连接，麦克风通道未就绪 | 心跳已通，但未收到音频/快捷键就绪状态，或状态已过期。先退出旧程序，只运行新版；检查 CABLE Input 和启动错误 |
| WinError 10048 / UDP 33333 绑定失败 | 端口被占用。退出旧的 `relay.py`、旧托盘或重复窗口；不要同时启动两个桥接程序 |
| 没找到 CABLE Input | 安装 VB-CABLE 并重启；`--list-devices` 检查，别把 CABLE Output 当播放出口 |
| 打开声卡失败 | 先关闭占用声卡的独占模式软件；本版会尝试同名不同后端，所有端点失败时不能使用硬件麦克风 |
| 显示就绪，按住后输入法不启动 | 就绪只验证配置语法和声卡出口，无法验证微信设置；核对左右 Shift、hold/tap、当前输入焦点与应用权限级别 |
| 输入法开启但没有文字 | 用 Windows 录音工具选择 CABLE Output，按住设备录音再回放；有声则查输入法麦克风选择、联网与识别服务，无声则查设备录音/UDP/声卡 |
| 能出字，但整句话都不准 | 本版已有此用户反馈，原因尚未定位。先检查 CABLE Output 原始录音：若失真/断续/太小，排查收音与传输；若清楚完整，则与同一句话使用电脑实体麦克风的识别结果对照，再查输入法音源、方言和识别设置。不要盲目增加麦克风增益，过大可能削波 |
| 电脑麦克风有声，设备却没声 | 输入法用了错误音源；选择 CABLE Output，暂时禁用实体麦克风对照后恢复 |
| 网络好但偶尔缺字 | 缩短设备与路由器距离，避开拥挤 Wi-Fi；UDP 丢包不补发，音频队列为低延迟会丢弃过旧数据；先等识别界面出现再说话 |
| 退出后键似乎一直按着 | 先松开并按一下对应实体快捷键；关闭多余桥接程序。程序在断链、采音超时和正常退出时会释放快捷键，但进程被强杀无法保证清理 |
| 按下键没有发送文本 | 这是当前设计：本版只映射语音键，发送/清空功能已移除；在电脑上核对并提交文字 |
| USB 插着却找不到麦克风 | 正常；USB 用于供电/烧录，语音走 Wi-Fi + 电脑转发器 + VB-CABLE |
| 烧录提示分区不一致 | 不执行升级，保留备份，核对硬件后按首次安装流程；不可跳过校验强刷 |

## 查找占用端口的进程

PowerShell 中执行：

```powershell
Get-NetUDPEndpoint -LocalPort 33333 | Select-Object LocalAddress,OwningProcess
Get-Process -Id 这里填上一步的进程号
```

只有明确确认是自己的旧语音程序后才关闭对应窗口/托盘。不要复制别人的 PID 去结束进程，
也不要批量结束所有 Python 进程。查询权限不足时从任务管理器核对程序。

## 广播发现失败

同一可信 LAN 内，广播受阻但设备与电脑仍允许单播互通时，可在 `voice-config.json` 的
`device_ip` 填设备实际局域网地址（从路由器客户端列表核对），然后重启转发器。
它不能绕过 AP 客户端隔离；设备地址变化后需同步修改或恢复空字符串。

## 不要混用旧固件与新电脑端

新版固件要求电脑发送 `pc.status`，包含 `audioReady` 和 `hotkeyReady`，约每秒更新。
只发送旧版 beacon 的程序会使设备显示“电脑已连接”却无法说话。
使用同一发布包中的固件和电脑程序，更新时一起更新，并完整退出旧进程。
